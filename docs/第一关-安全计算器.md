# 第一关：安全计算器工具

## 这一关做了什么

实现了一个**只能做数学运算**的计算器，并建立了工具注册机制。这是整个 Agent 系统的最底层——Agent 要能做事，首先得有工具可用。

## 解决了什么问题

Agent 需要执行用户请求（如"计算 (12+8)*3"），但如果直接用 Python 的 `eval()` 执行用户输入的字符串，攻击者可以注入 `__import__("os").system("rm -rf /")` 这样的恶意代码，造成任意命令执行。

所以必须有一种**安全的方式来执行表达式**。

## 如何实现的

### 1. 用 ast 解析，而不是 eval 执行

```python
import ast
tree = ast.parse("12 + 8", mode="eval")
```

`ast.parse` 只做**语法分析**，把字符串变成一棵树，不会执行任何代码。例如：

```
"12 + 8"  →  ast.BinOp(left=Constant(12), op=Add(), right=Constant(8))
```

### 2. 白名单遍历，拒绝一切非数学内容

手动写一个递归函数 `_eval_node`，只认识四种节点：

| AST 节点类型 | 含义 | 允许的操作 |
|---|---|---|
| `ast.Constant` | 数字字面量 | 直接返回数值 |
| `ast.BinOp` | 二元运算（+、-、*、/） | 递归计算左右两边 |
| `ast.UnaryOp` | 一元运算（正号、负号） | 递归计算操作数 |
| `ast.Expression` | 外层包装 | 剥掉，取 `.body` |

**其他所有节点类型（函数调用、变量名、属性访问等）一律抛出 ValueError。**

### 3. 运算符映射表

```python
_BINOPS = {
    ast.Add: op.add,     # +
    ast.Sub: op.sub,     # -
    ast.Mult: op.mul,    # *
    ast.Div: op.truediv, # /
}
```

没有 `ast.Pow`（幂运算），所以 `2**10` 也会被拒绝。白名单天然限制了能力边界。

### 4. 工具注册表

```python
TOOLS = {
    "calculator": calculator,
}
```

一个简单的字典，将来 Agent 框架通过 `TOOLS["calculator"]` 按名字查找并调用函数。这是"工具注册"的最小原型。

## 测试覆盖

| 测试用例 | 验证内容 |
|---|---|
| `(12 + 8) * 3` → `"60"` | 括号和运算优先级 |
| `-5 + 2` → `"-3"` | 一元负号 |
| `10 / 4` → `"2.5"` | 浮点除法 |
| `__import__("os")` 被拒绝 | 代码注入防护 |
| 变量名 `x + 1` 被拒绝 | 变量引用防护 |
| 属性访问 `(1).__class__` 被拒绝 | 对象链攻击防护 |

## 核心设计决策

**为什么不用 eval？** 因为 `eval()` 会执行任意 Python 表达式，即使设置 `{"__builtins__": {}}` 也存在大量绕过方式。而 ast 白名单从结构上杜绝了非数学内容——不在列表里的节点类型根本无法通过。

**为什么返回字符串？** Agent 框架中，工具结果最终要作为文本喂给 LLM，返回字符串可以保持接口一致性。
