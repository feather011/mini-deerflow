## 第三部分：Phase 25 Lead Agent 架构

### 25A 已冻结的设计

#### 两类枚举必须分离

```
ExecutionRoute: direct_agent / tool / subagent / subagent_batch
ResourceAccessMode: read / write / unknown
```

#### LeadRun 状态

```
CREATED → PLANNING → ROUTING → EXECUTING → VERIFYING
    ↓                              ↓
WAITING_FOR_INPUT ←───────────────↓
    ↓
SYNTHESIZING → SUCCEEDED / PARTIAL / FAILED / CANCELLED / TIMED_OUT
```

终态：`SUCCEEDED / PARTIAL / FAILED / CANCELLED / TIMED_OUT`

澄清流程必须是：`PLANNING 或 VERIFYING → WAITING_FOR_INPUT → PLANNING`

#### 资源冲突语义

- 路径型资源：统一分隔符、折叠 `.`、拒绝 `..`、`casefold()`
- 逻辑型资源：大小写精确匹配
- 路径父子关系视为重叠区域
- READ/READ 可并行；WRITE/WRITE、READ/WRITE 冲突
- 任一 UNKNOWN 强制串行

#### Root Budget 与 Lease 语义

```
创建 Lease：只产生预留，不增加 root_usage
Lease 消费：减少 remaining_reserved，同时增加 lease.consumed 和 root_usage
关闭 Lease：只释放未消费预留
已消费额度：永不归还
Direct 调用：不能抢占活动 Lease 已经预留的额度
```

### 25B 真假覆盖审计（门禁通过后必须做）

1. **Root Budget 与 Lease**：两个 Lease 合计不能突破 Root Budget，Lease 的模型调用会增加根 `model_calls`
2. **持久化优先**：外部调用前必须先 SQLite 持久化，失败时内存不变
3. **SQLite CAS**：两个独立连接、严格一个成功、另一个得到 `LeadRunConflictError`、不泄漏 `OperationalError`
4. **SQLite 错误映射**：只有 `SQLITE_BUSY/SQLITE_LOCKED`、revision 不匹配、并发竞争才映射 Conflict
5. **Event 与恢复**：`event.run_id == state.lead_run_id`；`restore_usage()` 只对全新未消费 Budget 恢复一次

### 25C Planner 冻结方向

```
GoalContract
    ↓
Planner 读取当前 VerifiedFacts 与剩余预算
    ↓
只生成下一批 WorkItemProposal
    ↓
确定性 validate_batch
    ├─ 信息不足 → WAITING_FOR_INPUT
    ├─ 批次非法 → Planner 修正（受重试/预算限制）
    └─ 合法 → ROUTING
```

Planner 必须：不生成完整固定 DAG、使用已验证事实、默认最少工作项和 Subagent、信息不足时选择澄清、不执行工具不创建 Subagent 不写 Thread。

## 第五部分：UX-1 输入与发送体验

### 状态分离原则（强制）

| 维度 | 状态机 |
|------|--------|
| 消息提交 | `idle` / `pending` / `submitted` / `unknown` / `failed` |
| 任务结果 | `idle` / `running` / `succeeded` / `failed` / `stopped` |
| SSE 连接 | `idle` / `connecting` / `streaming` / `closed` / `errored` |

关键规则：
- SSE error → `unknown`（不标 failed，不引导重复执行）
- `run.failed` ≠ 用户消息没发出去；用户气泡保留 `submitted`
- 提交状态独立成气泡标记；连接断了不动用户消息状态

## 第十一部分：Middleware 的统一理解

```
Agent       = 做什么
Middleware  = 做事时共同遵守的规则
Runtime     = 谁创建、持有、关闭资源
Store       = 状态保存在哪里
API         = 外部如何调用
```

适合 Middleware：Logging / Trace / Retry / Budget / 指标 / Guardrail / 调用上下文
不应塞入 Middleware：Planner / Router / Reviewer / LeadRun 状态机 / Thread 提交 / 文件逻辑根选择
