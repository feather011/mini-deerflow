# 第三关：命令行界面

## 这一关做了什么

给 Agent 加了一个可以和人对话的命令行入口。用户在终端输入问题，Agent 回答，直到用户退出。同时支持 `--trace` 参数，可以看到 Agent 每一步的决策过程。

## 解决了什么问题

前两关的 Agent 只能在测试代码里调用，普通人没法用。CLI 是让 Agent 能被使用的最基础方式——打开终端，输入问题，得到答案。

## 如何实现的

### 1. 职责分离：CLI 只管输入输出

整个 CLI 代码只有两个函数，各管一件事：

```
main()         →  交互循环：读输入、调 Agent、打结果
format_trace() →  把轨迹数据变成可读字符串
```

Agent 的决策逻辑、模型的判断、工具的执行，CLI 一行都不碰。它只是"传话的"：

```
用户键入 → CLI 原样传给 Agent → Agent 返回答案 → CLI 原样打印
```

### 2. format_trace：纯函数

```python
def format_trace(trace: list[dict]) -> str:
```

接收 Agent 返回的轨迹列表，返回格式化字符串。纯函数意味着：相同输入永远得到相同输出，没有副作用，可以单独测试。

轨迹中每种 action 的展示方式：

| action | 显示内容 |
|---|---|
| `model_decision` | `[步骤 N] 模型决策: 调用工具 xxx，参数: ...` |
| `tool_call` | `[步骤 N] 工具调用: xxx('参数') → 结果` |
| `final_answer` | `[步骤 N] 最终回答: ...` |

### 3. main()：交互循环

```python
def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--trace", action="store_true")
    args = parser.parse_args()

    agent = Agent(model=FakeModel(), tools=TOOLS)

    while True:
        user_input = input("\n> ").strip()
        if user_input.lower() in ("exit", "quit"):
            break
        answer, trace = agent.run(user_input)
        if args.trace:
            print(format_trace(trace))
        print(answer)
```

关键点：
- `argparse` 处理命令行参数（`--trace`）
- `while True` 循环持续读取输入
- `exit`/`quit` 退出循环
- `EOFError`/`KeyboardInterrupt` 处理 Ctrl+C 和管道输入

### 4. 命令入口

在 `pyproject.toml` 中添加：

```toml
[project.scripts]
mini-deerflow = "mini_deerflow.cli:main"
```

安装后可以直接在终端运行 `mini-deerflow`，不需要 `python -m`。

### 5. 使用示例

```bash
# 普通模式
$ mini-deerflow
Mini DeerFlow（输入 exit 或 quit 退出）

> 计算 (12 + 8) * 3
计算结果: 60

> 你好
当前只支持计算功能，请输入以'计算'开头的表达式。

> exit
再见！

# Trace 模式
$ mini-deerflow --trace
Mini DeerFlow（输入 exit 或 quit 退出）

> 计算 10 + 5
--- 执行轨迹 ---
  [步骤 1] 模型决策: 调用工具 calculator，参数: 10 + 5
  [步骤 1] 工具调用: calculator('10 + 5') → 15
  [步骤 2] 最终回答: 计算结果: 15
--- 结束 ---

计算结果: 15
```

## 为什么 CLI 不应该包含 Agent 决策逻辑

CLI 的职责是**输入输出**，Agent 的职责是**调度决策**。如果把决策逻辑塞进 CLI：

1. **不可测试** — 决策逻辑依赖 stdin/stdout 就没法单元测试
2. **不可复用** — Web 界面、API 服务也需要同样的逻辑，就得复制代码
3. **违反单一职责** — 同一个函数既管交互又管决策，越改越乱

正确的分层：

```
用户 ←→ CLI（输入输出）
              ↓
          Agent（调度决策）
              ↓
          Model（思考判断）
              ↓
          Tool（执行动作）
```

每一层只做一件事，通过接口通信。这是整个 mini-deerflow 的核心架构原则。
